== Automation Decisionsリソース入門

Automation Controllerと同様に、イベント駆動型Ansibleでも、Rulebookを有効化してイベントをリッスンする前に、いくつかのリソースを設定する必要があります。主に扱うリソースは3種類あります。

[IMPORTANT]
.Ansible Automation Platform (AAP) の認証情報
====
* **ユーザー名:** `admin`
* **パスワード:** `ansible123!`
====

[IMPORTANT]
.Gitea の認証情報
====
* **ユーザー名:** `student`
* **パスワード:** `learn_ansible`
====

=== 認証情報 (Credentials)

イベント駆動型Ansibleの認証情報は、プライベートリポジトリからコンテンツを取得したり、外部のイベントソースに接続したり、受信Webhookをセキュアにするために使用されます。このラボではパブリックリポジトリを使用するため、ソース管理の認証情報を作成する必要はありません。

NOTE: 詳細については、公式ドキュメントを参照してください: link:https://docs.redhat.com/en/documentation/red_hat_ansible_automation_platform/2.5/html/using_automation_decisions/eda-credentials[Using automation decisions: Chapter 2. Credentials].

=== Decision Environment

Decision Environmentは、Rulebookの実行に必要なすべての依存関係（ソースプラグインを含むCollectionなど）をバンドルしたコンテナイメージです。これらは、Playbookの実行に使用されるExecution Environmentと概念的に似ています。例えば、Dynatraceからイベントを受信するには、`dynatrace.event_driven_ansible` Collectionを含むDecision Environmentが必要になります。

. **デフォルトのDecision Environmentを探索します。** `AAP`タブで、**Automation Decisions** → **Decision Environments** に移動します。 "Default Decision Environment" という名前の事前設定済み環境が表示されます。この環境はRed Hatによって配布されており、`ansible.eda` Collectionが含まれています。これにはAWS SQS、Kafka、そして（後ほど使用する）Alertmanagerなどのソースに対応するソースプラグインが含まれています。
+
image::Oct-17-2024_at_13.03.31-image.png[Decision Environment一覧画面, opts="border"]

NOTE: 詳細については、公式ドキュメントを参照してください: link:https://docs.redhat.com/en/documentation/red_hat_ansible_automation_platform/2.5/html/using_automation_decisions/eda-decision-environments[Using automation decisions: Chapter 5. Decision environments].

== タスク: EDAプロジェクトのインポート

イベント駆動型Ansibleにおける**プロジェクト**は、Rulebookを含むソース管理リポジトリです。このラボのプロジェクトには、Alertmanager用のRulebookが含まれています。これからこのプロジェクトをインポートします。

. **プロジェクトページに移動します。** `AAP`タブで、**Automation Decisions** → **Projects** に進みます。
. **Create project**ボタンをクリックして、新しいプロジェクトを作成します。
+
image::Oct-17-2024_at_13.06.48-image.png[Create projectボタン, opts="border"]
. **プロジェクトの詳細を入力します。** 以下の詳細でフォームに入力してください。
+
[cols="1,2a"]
|===
| キー | 値
| *Name* | `My EDA project`
| *Description* | `Project containing Event-Driven Ansible content`
| *Organization* | `Default`
| *Source control URL* | `http://gitea:3000/student/eda-project`
| *Source control credential*| _空欄のままにします_ (これはパブリックリポジトリです)
|===
. **プロジェクトを保存し、同期します。** **Create project**をクリックします。成功すると、ステータスが**Completed**と表示されます。リポジトリ内のファイルに変更を加えた場合は、「Sync project」ボタンを使用してプロジェクトを再同期する必要があります。
+
image::Oct-17-2024_at_13.10.35-image.png[プロジェクト同期成功の画面, opts="border"]
+
NOTE: 詳細については、公式ドキュメントを参照してください: link:https://docs.redhat.com/en/documentation/red_hat_ansible_automation_platform/2.5/html/using_automation_decisions/eda-projects[Using automation decisions: Chapter 4. Projects].
. **(任意) インポートしたプロジェクトを探索します。** インポートしたコンテンツを確認するには、`Gitea`タブに移動してログインします。`eda-project`リポジトリには、いくつかのRulebook（次で使用する`alertmanager.yml`を含む）と`playbooks`ディレクトリが含まれています。Rulebookは、Playbookのファイル名ではなく、Automation Executionの*テンプレート名*を参照することに注意してください。
